1. What We Are Building (Plain Words)

Think of it like Loom / OBS-lite. The app should let a user:

  • Turn on webcam — small camera preview (like a bubble, optional overlay on the recording).
  • Choose what to record — a popup where user picks: entire screen, one window, or one browser tab.
  • Start button — begins recording video (and usually audio too).
  • Stop button — ends the recording.
  • Save button — downloads/saves the recorded video file (usually .webm or .mp4) to the user's computer.

The two key browser technologies that make this possible are:

  1. getDisplayMedia() — asks the OS to show a "pick a screen/window/tab" popup and gives you that video as a stream.
  2. MediaRecorder — takes any video/audio stream and records it into a file in memory, which you can then save.

2. Core Web APIs You Need to Know

2.1 navigator.mediaDevices.getDisplayMedia()

This is the API that shows the browser's native "Choose what to share" window — the same popup you see on Google Meet/Zoom when sharing your screen. The browser itself provides the UI for choosing Screen / Window / Tab — you do not need to build that selection UI yourself, the browser gives it for free.

const screenStream = await navigator.mediaDevices.getDisplayMedia({
  video: { frameRate: 30 },
  audio: true // captures system/tab audio if user allows it
});
Simple way to understand it: This function returns a "stream" — think of a stream like a live pipe of video frames (and maybe audio) coming from whatever the user picked.

2.2 navigator.mediaDevices.getUserMedia()

This gets access to the webcam and microphone (separate from screen).

const camStream = await navigator.mediaDevices.getUserMedia({
  video: true,
  audio: true
});

You show this in a small <video> element (muted, autoplay) as the "camera preview bubble".

2.3 MediaRecorder

This is the actual "recorder". You give it a stream, call .start(), and it collects data chunks as the recording happens. When you call .stop(), you combine those chunks into one file (a Blob) which you can download.

const recorder = new MediaRecorder(stream, { mimeType: 'video/webm; codecs=vp9' });
let chunks = [];

recorder.ondataavailable = (e) => chunks.push(e.data);
recorder.onstop = () => {
  const blob = new Blob(chunks, { type: 'video/webm' });
  const url = URL.createObjectURL(blob);
  // use url to preview or download
};

recorder.start();
// later...
recorder.stop();

2.4 Combining Screen + Webcam (optional but common)

If you want the webcam bubble to actually be "baked into" the saved video (like Loom does), you need to merge both streams visually using an HTML <canvas>:

  1. Draw the screen-share video frame onto a canvas every frame (using requestAnimationFrame).
  2. Draw the webcam video frame on top, in a corner, as a small circle/rectangle.
  3. Capture the canvas itself as a stream using canvas.captureStream(30).
  4. Feed that combined stream into MediaRecorder instead of the raw screen stream.
Simpler alternative: If you don't need the webcam burned into the video, just record the screen stream and show webcam only as a live preview (not saved). Much simpler to build — good for a first version.

3. Web App — Step by Step Build

1
Build the UI: A video preview area (big — for screen), a small video preview (webcam bubble), and 3 buttons: Start, Stop, Save. Also a dropdown/info text showing what's about to be captured.
2
On "Start" click:
  1. Call getDisplayMedia() → this pops up the browser's native screen/window/tab picker automatically.
  2. Call getUserMedia() → gets webcam feed (optional).
  3. If combining, set up a canvas + requestAnimationFrame loop to merge both feeds.
  4. Create a MediaRecorder on the final stream, and call .start().
3
On "Stop" click: call recorder.stop() and also stop all the individual media tracks (track.stop()) so the "sharing" indicator in the browser goes away and camera/mic are released.
4
On "Save" click (or automatically after stop): take the recorded Blob, create a temporary link element with download attribute, and click it programmatically — this triggers the browser's normal file save/download.
5
Bonus: Also show a <video> playback preview of the recorded Blob right after stopping, so the user can review before saving.

4.2 recorder.js

let mediaRecorder;
let recordedChunks = [];
let screenStream, camStream;

const screenPreview = document.getElementById('screenPreview');
const camPreview = document.getElementById('camPreview');
const startBtn = document.getElementById('startBtn');
const stopBtn = document.getElementById('stopBtn');
const saveBtn = document.getElementById('saveBtn');

startBtn.onclick = async () => {
  recordedChunks = [];

  // 1. Ask user to pick screen / window / tab (native browser popup)
  screenStream = await navigator.mediaDevices.getDisplayMedia({
    video: { frameRate: 30 },
    audio: true
  });

  // 2. Get webcam (optional, just for preview here)
  try {
    camStream = await navigator.mediaDevices.getUserMedia({ video: true, audio: false });
    camPreview.srcObject = camStream;
  } catch (e) {
    console.log('No webcam available or permission denied');
  }

  screenPreview.srcObject = screenStream;

  // 3. Set up recorder on the screen stream
  mediaRecorder = new MediaRecorder(screenStream, { mimeType: 'video/webm; codecs=vp9' });

  mediaRecorder.ondataavailable = (e) => {
    if (e.data.size > 0) recordedChunks.push(e.data);
  };

  mediaRecorder.onstop = () => {
    saveBtn.disabled = false;
  };

  mediaRecorder.start();

  startBtn.disabled = true;
  stopBtn.disabled = false;

  // If user stops sharing from the browser's own "Stop sharing" bar
  screenStream.getVideoTracks()[0].onended = () => stopBtn.onclick();
};

stopBtn.onclick = () => {
  mediaRecorder.stop();
  screenStream.getTracks().forEach(track => track.stop());
  if (camStream) camStream.getTracks().forEach(track => track.stop());

  startBtn.disabled = false;
  stopBtn.disabled = true;
};

saveBtn.onclick = () => {
  const blob = new Blob(recordedChunks, { type: 'video/webm' });
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = `recording-${Date.now()}.webm`;
  document.body.appendChild(a);
  a.click();
  a.remove();
  URL.revokeObjectURL(url);
  saveBtn.disabled = true;
};
That's a fully working web version in ~60 lines. The browser itself handles the "choose window/screen/tab" step — you never build that picker manually on the web.

5. Turning It Into a Desktop App (Electron)

Electron lets you package a website (HTML/CSS/JS) into a real installable desktop app (.exe / .dmg / .AppImage), using Chromium + Node.js under the hood. Good news: 90% of your web code stays exactly the same. The only real change is how you get the list of screens/windows to record, because on desktop, the browser's automatic picker isn't used — instead Electron gives you a raw list via an API called desktopCapturer, and you build your own little "choose a window" UI (a grid of thumbnails) instead of relying on the browser's popup.

5.1 Electron Architecture (simple explanation)

Main Process
(Node.js, controls windows, OS access)
↔ IPC ↔
Renderer Process
(Your HTML/CSS/JS — the UI)
↔ preload.js ↔
Secure Bridge
(exposes only safe functions)
  • Main process (main.js) — the "backend" of your desktop app. Creates windows, and can call desktopCapturer.getSources() to list all available screens/windows with thumbnail images.
  • Renderer process — this is literally your existing web app UI (index.html + recorder.js), running inside a Chromium window.
  • Preload script — a safe "bridge" file that exposes only specific functions from Main to the Renderer (best practice = keep contextIsolation: true and nodeIntegration: false for security).

5.2 Step-by-step

1
Install Electron: npm install --save-dev electron
2
Create main.js — creates the app window and handles a request "give me the list of sources" using desktopCapturer.getSources().
3
Create preload.js — exposes a safe function like window.electronAPI.getSources() to your existing renderer code.
4
Reuse your existing index.html and recorder.js — just add a small screen/window picker (a grid of thumbnails) instead of calling getDisplayMedia() directly with the browser popup.
5
When user clicks a thumbnail, call getUserMedia() with a special constraint pointing at that specific source id — Electron supports this via chromeMediaSourceId.
6
Everything else — MediaRecorder, Start/Stop/Save — stays 100% identical to the web version.

6. Electron — Full Working Code

6.1 main.js

const { app, BrowserWindow, ipcMain, desktopCapturer } = require('electron');
const path = require('path');

function createWindow() {
  const win = new BrowserWindow({
    width: 1000,
    height: 700,
    webPreferences: {
      preload: path.join(__dirname, 'preload.js'),
      contextIsolation: true,
      nodeIntegration: false
    }
  });
  win.loadFile('index.html');
}

// Renderer asks: "give me the list of screens/windows"
ipcMain.handle('get-sources', async () => {
  const sources = await desktopCapturer.getSources({
    types: ['window', 'screen'],
    thumbnailSize: { width: 200, height: 150 }
  });
  // Send only serializable data (thumbnail as data URL, not the raw object)
  return sources.map(s => ({
    id: s.id,
    name: s.name,
    thumbnail: s.thumbnail.toDataURL()
  }));
});

app.whenReady().then(createWindow);
app.on('window-all-closed', () => { if (process.platform !== 'darwin') app.quit(); });

6.2 preload.js

const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('electronAPI', {
  getSources: () => ipcRenderer.invoke('get-sources')
});

6.4 Updated recorder.js (Electron version — only the "start" logic changes)

startBtn.onclick = async () => {
  const sources = await window.electronAPI.getSources();
  const grid = document.getElementById('sourceGrid');
  grid.innerHTML = '';

  sources.forEach(source => {
    const img = document.createElement('img');
    img.src = source.thumbnail;
    img.title = source.name;
    img.style.cursor = 'pointer';
    img.style.border = '2px solid #444';
    img.onclick = () => startRecordingFromSource(source.id);
    grid.appendChild(img);
  });

  document.getElementById('pickerModal').style.display = 'block';
};

async function startRecordingFromSource(sourceId) {
  document.getElementById('pickerModal').style.display = 'none';
  recordedChunks = [];

  // Special Electron-only constraint format to target a specific window/screen
  screenStream = await navigator.mediaDevices.getUserMedia({
    audio: false,
    video: {
      mandatory: {
        chromeMediaSource: 'desktop',
        chromeMediaSourceId: sourceId
      }
    }
  });

  screenPreview.srcObject = screenStream;

  // ---- everything below this line is IDENTICAL to the web version ----
  mediaRecorder = new MediaRecorder(screenStream, { mimeType: 'video/webm; codecs=vp9' });
  mediaRecorder.ondataavailable = (e) => { if (e.data.size > 0) recordedChunks.push(e.data); };
  mediaRecorder.onstop = () => { saveBtn.disabled = false; };
  mediaRecorder.start();

  startBtn.disabled = true;
  stopBtn.disabled = false;
}
Key idea to remember: On the web, the browser shows the picker automatically via getDisplayMedia(). On Electron desktop, you fetch the list yourself via desktopCapturer (Main process) and build your own picker UI, then feed the chosen source id into getUserMedia() with a special chromeMediaSourceId constraint. Stop / Save / MediaRecorder logic does not change at all.

7.1 Bonus: Saving directly to disk in Electron (nicer than browser download)

// In renderer, after recorder.onstop:
mediaRecorder.onstop = async () => {
  const blob = new Blob(recordedChunks, { type: 'video/webm' });
  const buffer = Buffer.from(await blob.arrayBuffer());
  window.electronAPI.saveRecording(buffer); // sent to main process via preload
};

// preload.js — add:
saveRecording: (buffer) => ipcRenderer.invoke('save-recording', buffer)

// main.js — add:
const fs = require('fs');
const { dialog } = require('electron');

ipcMain.handle('save-recording', async (event, buffer) => {
  const { filePath } = await dialog.showSaveDialog({
    defaultPath: `recording-${Date.now()}.webm`,
    filters: [{ name: 'Videos', extensions: ['webm'] }]
  });
  if (filePath) fs.writeFileSync(filePath, buffer);
});

This gives a proper native "Save As" dialog instead of always dumping into the Downloads folder — a nice touch that makes the desktop app feel more "native".

8. Full Tech Stack Recommendation

8.1 Minimum stack (fastest to build, good for MVP)

LayerChoiceWhy
FrontendPlain HTML + CSS + Vanilla JSNo build step, you already saw it works in ~60 lines
RecordingMediaRecorder + getDisplayMedia/getUserMediaBuilt into every modern browser, zero dependencies
Desktop wrapperElectronReuses the same web code almost unchanged
Packagingelectron-builderProduces .exe (Windows), .dmg (Mac), .AppImage/.deb (Linux)

8.2 More "production-grade" stack (recommended if this becomes a real product)

LayerChoiceNotes
UI FrameworkReact (with Vite) or SvelteEasier to manage state — start/stop/recording-time/preview etc. React works identically in Electron's renderer.
StylingTailwind CSSFast to build a clean modern UI, works in both web and Electron.
State managementZustand or React ContextTrack recording state (idle/recording/paused/saved).
Recording engineMediaRecorder API (native)Still the core — no need for a heavy library for basic recording.
Video encoding/trimming (optional, advanced)ffmpeg.wasm (browser) or native ffmpeg via child_process (Electron)Useful if you want to convert webm → mp4, trim, or compress after recording.
Desktop shellElectronOr "Tauri" (Rust-based) as a lighter, smaller-binary alternative if you don't need heavy Node APIs.
Auto-updateelectron-updaterLets your desktop app auto-update itself.
Packaging/Installerselectron-builderGenerates signed installers per OS.
Storage of past recordings (optional)IndexedDB (web) / local filesystem (Electron)If you want a "history / library" of recordings inside the app.
Backend (only if you need cloud save/sharing)Node.js + Express, or FirebaseOnly needed if recordings should be uploaded/shared, not required for local-only recording.

8.3 Alternative to Electron: Tauri

Worth knowing: Tauri is a newer alternative to Electron. It uses the OS's native web-renderer instead of bundling a full Chromium, so apps are much smaller (~10MB vs ~150MB) and use less memory. The trade-off is it uses Rust for the backend/main-process logic instead of Node.js, so there's a small learning curve. For a first version, Electron is simpler because everything stays in JavaScript.

9. Packaging & Distribution

npm install --save-dev electron-builder

Add this to package.json:

"scripts": {
  "start": "electron .",
  "build": "electron-builder"
},
"build": {
  "appId": "com.yourname.screenrecorder",
  "win": { "target": "nsis" },
  "mac": { "target": "dmg" },
  "linux": { "target": "AppImage" }
}

Then run npm run build — it produces a ready installer file per platform inside a dist/ folder.

10. Common Problems & Fixes

ProblemFix
Black screen when recording certain windows (Windows OS)Some apps use hardware-accelerated rendering that blocks capture — this is an OS limitation, not a bug in your code.
No audio in recordingSystem audio capture support varies per OS/browser; on Electron, capturing system audio usually needs an extra native module or platform-specific workaround — mic-only audio is the reliable option.
getDisplayMedia is not a function in Electron rendererElectron's renderer does support it, but you must NOT set nodeIntegration:true carelessly — and for Electron you'll typically use the desktopCapturer approach instead anyway.
File saved as .webm but user wants .mp4webm is native to MediaRecorder; converting to mp4 needs ffmpeg (either ffmpeg.wasm in browser, or a bundled ffmpeg binary in Electron).
App keeps showing "sharing" indicator after stopMake sure you call track.stop() on every track in the stream, not just mediaRecorder.stop().
Permissions denied for screen/micWeb: must be served over HTTPS (or localhost) — it won't work on plain HTTP. Electron: ensure correct entitlements are set, especially on macOS (Screen Recording permission in System Settings).
